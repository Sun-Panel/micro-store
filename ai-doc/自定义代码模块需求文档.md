# 自定义代码模块（custom_code）需求文档

> 状态：**已确认（v2 结构版）**
> 创建日期：2026-09-18　　更新日期：2026-09-19
> 适用范围：sun-panel-micro-store（前端 + 后端）
> 说明：本文中的「帖子」即一条「自定义代码」（custom_code）记录

> **v2 变更要点**：放弃富文本编辑器，内容改为**结构化代码片块**；新增**适用客户端版本**字段。
> 目的：便于后期深度集成到 Sun Panel 客户端（客户端可直接按块取用 JS/CSS/页脚代码）。

---

## 1. 背景与目标

用户可以在站点发布自定义的 JS / CSS / 页脚代码，用来美化或扩展 Sun Panel 面板。为保证内容质量与安全，帖子需经过审核员审核通过后才能在前台展示；作者修改内容后需重新审核，且**审核期间前台继续使用上一次已通过的版本**。

核心目标：

1. 开发者可发布自定义代码帖（结构化代码片块 + 说明 + 预览图）。
2. 审核员可审核；支持通过 / 拒绝并填写备注。
3. 修改需重新审核；审核期间旧版本继续生效。
4. 前台有帖子列表与详情页，代码高亮、默认折叠、支持一键复制。
5. 复制 JS 时自动补全闭包匿名函数；复制 CSS / JS / 页脚 HTML 时自动加上来源注释。
6. 统计阅读量；记录「作者发布/修改时间」而不是数据库行变更时间。
7. **数据按"块"结构化存储，为客户端集成预留消费能力。**

## 4. 业务流程与状态机

### 4.1 主表状态（线上状态）

| 值 | 含义 | 前台可见 |
|---|---|---|
| -1 | 草稿 | 否 |
| 0 | 待审核（首次提交，从未上线） | 否 |
| 1 | 已上线 | 是 |
| 2 | 已拒绝（从未上线） | 否 |
| 3 | 已下架 | 否 |

### 4.2 快照表状态（某次提交的审核状态）

| 值 | 含义 | 作者可否编辑 |
|---|---|---|
| -1 | 草稿（保存未提交 / **已撤回**） | ✅ |
| 0 | 待审核 | ❌ 只读，需先撤回 |
| 1 | 已通过 | ✅（再编辑会生成新快照） |
| 2 | 已拒绝 | ✅（展示拒绝原因） |

### 4.3 流程

1. 新建草稿 → 主表 -1 + 快照 -1。
2. 提交审核 → 快照 0；首次提交主表 0。**提交时把块复制为快照块（`review_id=快照ID`）**。
3. 首次通过 → 快照字段写入主表 + **快照块覆盖为线上块（`review_id=0`）** → 主表 1、`published_at=now()`。
4. 首次拒绝 → 快照 2 + 备注 → 主表 2。
5. 修改已上线帖子 → 新快照 0（含块副本）→ **主表与线上块不变，前台继续用旧版本**；编辑页只读。
6. **撤回审核** → 快照 0 → -1，恢复可编辑。
7. 修改通过 → 覆盖主表 + 块；修改拒绝 → 主表与线上块不变。
8. 下架 / 强制下架 → 主表 3（管理员带 `offline_reason`）。

> 覆盖线上块的操作必须在**事务**中完成，避免中途失败造成半更新。

## 5. 数据表设计

### 5.1 `custom_code`（主表 / 线上内容）

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | varchar(100) not null | 标题 |
| `description` | varchar(500) not null | 说明 |
| `keywords` | varchar(500) | 关键词 JSON 数组 |
| `is_original` | tinyint(1) default 1 | 是否原创 |
| `source_note` | varchar(500) | 来源说明（非原创必填） |
| `versions` | varchar(50) not null | **适用客户端版本 JSON 数组**（1=v1，2=v2），至少 1 个，默认 v2 |
| `code_types` | varchar(50) not null | 代码类型 JSON 数组，**由块自动汇总**（不再由用户选择） |
| `author_id` | int(11) index | 作者 user_id |
| `status` | tinyint(2) index | 线上状态 |
| `read_count` | int(11) index | 阅读量 |
| `published_at` | datetime | 作者发布/修改时间 |
| `current_review_id` | int(11) | 当前生效快照 ID |
| `offline_reason` | varchar(500) | 下架原因 |

继承 `BaseModel`（id / created_at / updated_at / deleted_at）。
作者名不冗余：按 `author_id` 关联 `developer.developer_name`，无则 `user.name`。

### 5.2 `custom_code_block`（代码片块表）✅ 新增

| 字段 | 类型 | 说明 |
|---|---|---|
| `custom_code_id` | int(11) not null, index | 关联帖子 |
| `review_id` | int(11) not null, default 0, index | **0=线上块；非 0=某次审核快照的块** |
| `sort` | int(11) not null, default 0 | 排序（上移/下移） |
| `code_type` | tinyint(2) not null | 块内单选：1=JS 2=CSS 3=页脚 |
| `title` | varchar(100) | 块标题（与说明至少填一个） |
| `note` | text | 块说明（多行纯文本，前台保留换行） |
| `code` | longtext not null | **代码片段（纯文本，必填）** |
| `images` | varchar(1000) | 预览图 URL JSON 数组（≤5 张，单张 ≤512K） |

继承 `BaseModel`。索引：`(custom_code_id, review_id)`。

### 5.3 `custom_code_review`（快照表）

字段与主表一致（含 `versions`、`code_types`），**不再保存 `content`**（块内容通过 `custom_code_block.review_id` 关联）。
额外：`reviewer_id`、`review_note`、`review_time`、`status`。

### 5.4 迁移

```go
&models.CustomCode{},
&models.CustomCodeReview{},
&models.CustomCodeBlock{}, // 代码片块表
```

## 6. 校验规则

| 层级 | 规则 |
|---|---|
| 帖子 | 标题 ≤100 必填；说明 ≤500 必填；关键词 JSON 数组 ≤10 个 |
| 帖子 | **版本：v1/v2 多选，至少 1 个，进入编辑页默认选中 v2** |
| 帖子 | 非原创时来源说明必填 |
| 块 | 数量 **1 ~ 10** |
| 块 | 代码类型单选（JS/CSS/页脚） |
| 块 | **标题与说明至少填一个** |
| 块 | **代码片段必填**（纯文本） |
| 块 | 预览图每张 ≤512K，每块 ≤5 张 |

前端即时校验 + 后端兜底。

## 7. 代码高亮与复制

### 7.1 语言判定（不再猜测）

按块的代码类型直接映射：

| 块类型 | Prism 语言 |
|---|---|
| JS | javascript |
| CSS | css |
| 页脚 | markup |

### 7.2 高亮

前台与编辑页预览统一使用 `CodeBlock` 组件（Prism 高亮 + 折叠 + 复制）。

### 7.3 折叠

- **代码区默认折叠**，只显示块标题 / 说明 / 预览图。
- **复制按钮放在块头部操作区，折叠状态下同样可见**（不随代码隐藏）。
- 提供「全部展开 / 全部收起」。

### 7.4 注释头（复制时自动加）

JS / CSS：

```js
/*
Title: 帖子标题
Author: 作者
UpdateTime: 2026-09-19 15:30
URL: https://example.com/customCode/12
*/
```

页脚 HTML：

```html
<!--
Title: 帖子标题
Author: 作者
UpdateTime: 2026-09-19 15:30
URL: https://example.com/customCode/12
-->
```

### 7.5 JS 闭包补全

1. 已有 IIFE（`(...function...)()`、`(() => {})()`、`!function(){}()` 等）→ 不包裹
2. 含顶层 `import` / `export`（ES Module）→ 不包裹并提示
3. 其余 → 补 `;(function () { 'use strict'; ... })();`

## 8. 阅读量统计

- 主表 `read_count`，仅详情页 +1。
- 防刷：`IP + 帖子ID`（登录用户用 `userID`）缓存去重 **24 小时**；缓存不可用退化为每次 +1。

## 12. 技术要点与风险

1. **不再渲染 UGC HTML**：说明为纯文本（`white-space: pre-wrap`），代码为纯文本经 Prism 转义后输出。
2. **消毒依赖保留做兜底**：后端 `bluemonday`、前端 `dompurify` 均保留（后续若恢复富文本可直接使用）。
3. **块覆盖必须事务化**（审核通过时）。
4. **安全提示**：详情页仍展示"第三方 JS/CSS 可能影响面板安全，请自行判断后使用"。
5. **列表不返回 `code` 大字段**；详情接口才返回块代码。
6. **关键词搜索**用 `LIKE` 兼容 MySQL 与 SQLite。
7. **图片上传**复用上传目录 `/uploads`，额外限制 512K。

## 15. 验收要点

1. 编辑页版本默认选中 v2；至少选 1 个，不选无法提交。
2. 块可增删排序；块数量超过 10 时不允许继续添加。
3. 块标题与说明都不填时校验拦截；代码为空时校验拦截。
4. 预览图超过 512K 被拒绝；单块超过 5 张被拒绝。
5. 修改已上线帖子 → 前台仍是旧块；审核通过后前台变为新块，`published_at` 刷新。
6. 待审时编辑页只读，撤回后恢复可编辑，线上块不受影响。
7. 前台代码区**默认折叠**，复制按钮**折叠状态下可见可用**。
8. 复制 JS（无 IIFE）→ 自动补闭包；已有 IIFE 或 ESM → 不重复包裹。
9. 复制 JS/CSS → `/* */`；页脚 → `<!-- -->`；注释含正确的标题、作者、更新时间、URL。
10. 列表可按版本（v1/v2）与代码类型（JS/CSS/页脚）过滤。
11. 帖子类型的代码类型标签由块自动汇总，与用户实际添加的块一致。
